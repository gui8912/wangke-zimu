## 五、结论

**有条件通过。** 三个发现：

1. **顺滑效果真实存在。** 规则层删不掉「那么/那个/这个/就是说」这类指代性口语
   （它们后面跟着名词，删了会语句不通），LLM 能正确删除并重组句子。字数从 320 降到 252–266，
   语气从"讲"变成"读"。

2. **术语与数字零损伤。** 两品一械、药品经营质量管理规范、药品上市许可持有人、
   飞行检查、走票过票、一致性评价、中药饮片、UDI 全部原样保留。这一点比预期好。

3. **但会漏内容，而且反直觉：先规则清理反而更容易丢。**
   C（规则+LLM）把结尾「那今天就到这里，谢谢大家」整句删掉了，B（直接 LLM）没有。
   推测原因：规则清理先删掉一部分衔接词，剩下的文本更"紧"，模型更容易把它当冗余压缩。
   这说明**不能把 LLM 放在规则之后当最后一道**，而应二选一或都保留供对比。

## 六、接线方案（待确认）

如果要做，必须带三个护栏，缺一不可：

1. **只作用于讲稿轨**（`script` track），字幕轨一个字都不碰——沿用 v1.3 的双轨设计。
2. **强制 diff 预览**：生成后先出「原文 / 顺滑稿」逐段对比，采用前不影响任何导出。
3. **漏句检测**：把这次的 `coverage()` + 末句检查做成常驻校验，任一句丢失就标红并
   拒绝自动采用（这次就是靠它抓到 C 丢了结尾）。

默认关闭，独立开关，明确标注「会改措辞，不影响字幕与时间轴」。

**不建议**直接替换现有 `revise.py` 七遍改稿——那是"人主导、每遍只做一件事"的流程，
LLM 顺滑适合作为**第 0 遍**（把口语变成可读的底稿），之后仍走既有人工七遍。
