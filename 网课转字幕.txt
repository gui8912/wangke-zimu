网课转字幕工具（药品监管网课语音转字幕 / 文稿）

【用途】
把国内中文网课（药品、医疗器械监督管理等专业）的录音 / 录像，转成字幕（SRT / VTT）
或可编辑文稿（TXT / DOCX）。
- 适配专业术语，自动清理口语词（语气词、冗余、填充词等 100+ 条规则）
- 精度优先（Qwen3-ASR-1.7B，纯 CPU 约 1.37× 实时，1 小时课约 44 分钟），可接受慢
- 自带网页操作台：口语词编辑、播放器逐句校对、查找替换、截图、暗色护眼主题、七遍改稿
- 默认纯本地（音视频不出本机）；1.3 起可选云端识别源，内容不涉密时可用
- 1.4 起自动做「受限数字规整」：百分之九十八点五 → 98.5%，但法规条款号与
  监管术语（第一百二十条、四不两直）一字不动
- 1.5 起自动修复简称与漏字：GSP → 药品经营质量管理规范；
  药品经营质量规范 → 药品经营质量管理规范（只在依据/根据/《 等强上下文才自动改）
- 1.7 起可选「LLM 润色」：本地 Qwen3-4B 把口语整理成可读底稿（第 0 遍），
  只改讲稿，字幕与时间轴一个字不动；模型也在本机，音频同样不出机
- 1.8 修了 4 个会导致「静默出错」的缺陷（导出标点改坏英文缩写、模型输出
  被截断却不报警、润色卡死无法恢复、原子写并发冲突）
- 1.9 修了长课必崩的段错误：79 分钟课程整段送进识别模型会把进程撑死，
  现改为切 170 秒一片、逐片识别再拼回，长课不再中途消失
- 2.0 任务栏加了识别进度条（百分比 / 分片阶段 / 预计剩余）与批量操作：
  全选、反选、批量重试、批量取消、删除选中、清空已结束
- 2.1 分片并行识别：默认 2 路，实测 1.26–1.82 倍提速，文字与时间戳一致；
  ASR_QWEN3_WORKERS 可调（1 路最省内存，3 路最快）
- 2.2 「改稿」页 →「润色模型设置」可接智谱 GLM-4-Flash（永久免费）、
  DeepSeek V4-Flash（低价）或任意 OpenAI 兼容模型；识别永远本地，只有讲稿上云
- 2.3 批量夜间无人值守：一次拖入多节课、定时开始、暂停/继续、队列排序、
  文件夹监控、跳过已转录、失败自动重试、重启续跑、防休眠、队列汇总报告；
  命令行 batch_add.py + 启动批量任务.bat（详见 批量任务说明.txt）
- 完整操作请看《使用说明书.md》：单节课流程、批量夜间、成本账、参数速查、故障排查

【1.9 长音频段错误修复（2026-11-08）】
- 现场：服务空闲跑了 9 小时后接到一个 79 分钟课程，模型加载完 15 秒，进程直接
  消失（exit 139 段错误），任务状态永远停在 running、日志断在「模型就绪」，
  前端一句报错都没有
- 根因：Qwen3-ASR 这条路径把整段音频交给 model.transcribe()，库内部按 180 秒
  切成 27 片后「整批」送进前向（库默认批大小 32）。单次前向的 logits 就要几十 GB，
  进程被内存撑爆、段错误退出；原生崩溃在 Python 侧抓不到异常，只能表现为「任务消失」
- 附带发现：库默认 max_new_tokens=512，180 秒中文片段约 700 字，超出部分会被
  静默截断 —— 就算不崩，长课也会悄悄丢字
- 修复：
  ① 自己按 170 秒、低能量边界切片，逐片识别，内存恒定在单片水平；
     每片失败先重试一次，仍失败才报错，报错带片号与时间位置
     （如「第 12/28 片（33.4 分钟处）识别失败」）
  ② 片内字级时间戳统一加片偏移再拼接，align.py 对齐与波形显示都不受影响
  ③ 建模型时显式 max_inference_batch_size=1、max_new_tokens=2048
     （ASR_QWEN3_MAXTOK 可调）
  ④ 窗口夹在 30–175 秒、搜索半径压到窗口 1/6（ASR_QWEN3_WINDOW 可调）
     —— 窗口太小会让库的切片函数原地打转（实测 12 秒静音音频切出十几万片）
  ⑤ 服务启动开 faulthandler：再遇原生崩溃会把 Python 栈写进 out/_crash.log
  ⑥ 逐片进度写进任务日志（「识别 12/28（33.4 分钟）：486 字」），长课不再
     看起来像卡死
- 真机实测（真实课程第 5–11.7 分钟，共 400 秒）：切 3 片，出 1958 字、
  1786 个字级时间戳，耗时 279 秒（1.44 倍实时），内存峰值 8.8 GB
  —— 单片 170 秒就要 8.8 GB，原来 27 片同批前向意味着几十 GB 起步，
  63 GB 内存也扛不住，段错误是必然结果，不是偶发。所以 ASR_QWEN3_WINDOW
  不建议往上调，除非确认内存余量够
- 顺带修掉两处 1.8 漏网的原子写问题：任务状态文件 _persist 的临时名还是固定的
  <id>.tmp（1.8 只改了 _atomic_write），同时起两个实例会互相覆盖；os.replace
  在 Windows 上偶发 PermissionError（杀软/索引服务瞬时占用），现重试两次再报错
- 回归：python samples/test_v19.py（26 项）；真机验证
  python samples/probe_v19_longaudio.py

【1.8 源代码审计修复（2026-11-08）】
- 导出「标点全角化」原来只排除了「数字.数字」，英文缩写照样被改坏：
  GMP.GSP → GMP。GSP、No.5 → No。5、e.g. → e。g.（已实测）。
  现改为「前一个字符是中文、且后面不是数字」才转句号
- LLM 输出被 max_tokens 截断时原来不报警：llama.cpp 只把 finish_reason 置为
  length、不抛错，代码会把半截正文当完整结果（实测 343 字只剩 161 字）。
  现在检测到截断就抛 TruncatedOutput，并把该块对半切开重试（最多 2 层），
  切不动才报错 —— 宁可报错，不给残稿
- 润色接口原来没有超时：推理在 C++ 层跑、Python 中断不了，一旦卡死锁永远不释放，
  界面一直显示「正在润色」。现在正常占用返 409、超过 600 秒（ASR_LLM_TIMEOUT 可调）
  返 503 并明说请重启；前端另加 10 分钟自动断开兜底
- 原子写的临时文件名原来是固定的 <名字>.tmp，自动保存与手动保存并发时会互相覆盖；
  现改为加 8 位随机后缀，失败时清理，不在 out/ 留垃圾
- 其他：任务文件顶层不是对象时不再带崩启动；「重新清理」改为线程池执行、
  不再挡住其他请求；简称表拒绝「全称含简称」的自我膨胀配置；润色失败不再把
  内部路径回给前端；词表损坏时给明确原因；极短文本也报满五项硬红线；
  转写日志落盘节流到 1 秒一次；模型查找结果缓存 30 秒

【1.7 讲稿层 LLM 顺滑（2026-11-08）】
- 改稿页新增「LLM 润色」按钮，用本地 Qwen3-4B-Instruct（GGUF Q4_K_M，2.33GB，
  llama-cpp-python 纯 CPU）把口语转写整理成可读底稿，作为七遍改稿的第 0 遍
- 只作用于讲稿层，字幕（cues + 字级时间戳）一个字都不碰：
  整段改写会打断 align.py 的字级对齐、音画不同步，这条红线 1.3 就写死了
- 为什么直接对原文做：实测「先规则清理再交给模型」会把结尾
  「那今天就到这里，谢谢大家」整句删掉；「直接对原文」能保住（343→275 字）
- 三道闸门：
  ① 五项硬红线——术语保留（清单来自 terms/）/ 条款号 / 数字 / 末句 / 长度 0.6–1.25×，
     任一不过则「采用」按钮禁用。末句那项是专门加的：模型高频把结尾客套话当冗余删，
     而术语/数字/长度全过，几千字稿子里肉眼发现不了
  ② 逐句 diff + 润色后全文强制预览；接口本身不落盘，绕过预览没有保存入口
  ③ 采用后另起 stem（原stem_润色），原稿 v0 不动，随时可回溯
- 「残留口语」「内容覆盖」只作参考，不阻断采用：LLM 会重组句子，覆盖率低
  不必然等于丢内容；「这个/那个」后跟名词删了不通，正是 LLM 的增量
- 末句真被删了：弹窗底部给「补回原末句」，把原文最后一句原样接回去并重算长度项。
  不静默替模型补，否则闸门会变成永远通过、掩盖模型真实行为
- 实测：343 字 13.3 秒（12 线程 CPU，约 26 字/秒），1 万字约 6 分钟；
  单次上限 8000 字。模型常驻内存 2.4GB，首次点击才加载
- 模型缺失或 llama-cpp-python 未装：按钮置灰并写明原因，不伪造结果
- 模型目录默认 D://AI//models//llm，可用环境变量 ASR_LLM_DIR 改
- 回归：python samples/test_v17.py（18 项，不加载模型），全套 15 个脚本全绿

【1.5 术语修复与修订学习（2026-11-08）】
- 简称膨胀（terms/aliases.txt）：GSP / GMP / GVP / GCP / GLP / GAP → 全称。
  必须用显式表：实测 GSP 在 125 条术语表里模糊匹配只有 29 分，任何 fuzzy 都认不出。
  英文缩写按整词边界匹配，GSP认证 能展开，GDP / GSPX 不误伤
- 漏字补全（termfix.py）：药品经营质量规范 → 药品经营质量管理规范。三条硬约束：
  ① 只补比术语短的片段（否则「按照药品管理法实施条例」会把「按」吃掉）
  ② 首尾必须都对得上（漏字只在中间；「依据药品管理的规定」不会被补成「药品管理法」）
  ③ 强上下文才自动改（依据/根据/按照/《/第X条/规定/要求），弱上下文只出建议
  实测 4/5 正样本正确、6/6 负样本零误改；0.2 ms/句（加 3-gram 短路）
- 修订学习（learn.py + 校对工具条「学习建议」）：
  只观察不自动应用。同一处修改出现 ≥2 次才列为候选，逐条点「采纳」才写进词表。
  三条防污染：同内容只记一次（自动保存 1.2s 一次）；jieba 词级 diff（字符级会产出
  「营质量规范的」这种脏片段）；句子数差异过大判为换源，整次不学
- 顺带修两个真缺陷：
  ① P0：第二十条 曾被数字规整成 第二10条（(?<!第) 断言在「第X十Y」失效），
     改为整体遮蔽条款号后原样放回
  ② 字幕行原来不能点击跳转，校对只能拖进度条；现在单击整行跳到该句起点
- 语速含混救不了：多字连错超出 fuzzy 能力，只能提升识别、用 warn 标黄复核，
  或交给 LLM。最优解仍是讲义对齐（实测漏 2 字/漏 4 字/简称/同音错/含混
  相似度 0.900/0.875/0.889/0.955/0.850，全部能对齐且输出讲义原文）
- 开关：顶栏「术语补全」复选框、命令行 --no-termfix / --termfix-suggest-only
- 回归：samples/test_v15.py（18 项），全套 13 个脚本全绿

【1.4 受限数字规整（2026-11-08）】
- 背景：ASR 已商品化，真正的差距在转写之后；但市面 ITN 工具做的是全量规整，
  会把「第一百二十条」写成「第120条」、把「四不两直」改坏，监管材料不能用
- 做法：新增 itn_zh.py，白名单式，只转 5 类明确计量语境：
  百分比（百分之九十八点五→98.5%）、四位年份（二零二六→2026，限 1900-2100）、
  月日（六月一日→6月1日，月日越界不动）、数量词+单位（≥10 才转，
  三百五十家→350家，五十万元→50万元）、文号（第七百三十九号→第739号）
- 永不改动：法规条款号（第一百二十条/第五条第二款/第三章）、监管固定表达
  （四不两直、双随机一公开、四个最严、三品一械、十四五）、成语惯用语
  （一刀切、一揽子、第一时间）；各有一条回归用例守着
- 只用清理层：只影响 *.clean.srt / *.clean.txt，raw 原稿保持识别原样
- 为什么不用 wetext：依赖 pynini 需 OpenFst 本地编译，Windows 装不上；
  且它是全量 ITN，在本场景是负价值。本方案只依赖 cn2an（纯 Python），
  未装时自动跳过并告警，不影响其他功能
- 开关：顶栏「数字规整」复选框（默认勾选）、命令行 --no-itn、
  接口 itn=true|false（/api/transcribe、/api/reclean）
- 回归：python samples/test_itn.py（17 项），既有全套回归 12 个脚本全绿

【使用方法】
方式一 · 服务台（推荐）
1. 双击桌面「服务台」快捷方式，或运行 D:\Tools\服务台\启动服务台.bat
2. 在「自建应用」分组找到「网课转字幕」，点「启动」；浏览器自动打开 http://127.0.0.1:7870/
3. 停止：在服务台点「停止」，或直接关掉启动窗口

方式二 · 直接双击
- 双击「启动网课转字幕.bat」（原有的 启动界面.bat 亦可），浏览器自动开 7870
- 关闭该窗口即停止服务

方式三 · 命令行（批量 / 无界面）
- 单文件转写并清理：  python transcribe.py -i "课程.mp4" --clean
- 指定输出目录：      python transcribe.py -i "课程.mp4" -o out\
- 列出可用模型：      python transcribe.py --list-models
- 指定识别源：        python transcribe.py -i "课程.mp4" --provider local-qwen3
- 关闭数字规整：      python clean_transcript.py -i "课程.srt" --no-itn
- 关闭术语修复：      python transcribe.py -i "课程.mp4" --no-termfix
- 术语修复只建议：    python transcribe.py -i "课程.mp4" --termfix-suggest-only
- 云端源用整理稿：    python transcribe.py -i "课程.mp4" --provider tencent-cloud --use-script-track
- 仅清理已有文稿：    python clean_transcript.py 输入.txt
- 七遍改稿：          python revise.py 输入.txt

网页端功能
- 上传音频 / 视频 → 自动识别 → 字幕时间轴
- 「口语词」编辑窗口：空格分隔词条，实时增删规则
- 「识别源」下拉：默认本地；云端未配置或待接入时置灰并写明原因
- 「数字规整」复选框：默认勾选；取消则字幕保留纯汉字数字写法
- 「术语补全」复选框：默认勾选；取消则不动简称与漏字
- 「学习建议」按钮：显示你在校对里反复改的地方，逐条采纳后写入词表
- 「清理明细」按钮：逐条对照原文与清理结果，右侧标出触发原因
- 「LLM 润色」按钮（改稿页）：口语转可读底稿，先看红线与 diff 再决定采用
- 提示：润色若等太久（超过 10 分钟）界面会主动断开，此时请重启服务再试
- 下载菜单「导出设置…」：分段方式、段间空行、标点风格，设置本地保存
- 「整理稿对比」：仅云端整理稿可用，逐段 diff + 一键恢复识别原稿
- 播放器：点时间轴跳到对应字幕，逐句听校
- 查找替换、截图导出、暗色护眼主题（?theme=dark 或界面内切换）
- 导出场：SRT / VTT / TXT / DOCX

【原理步骤】
1. 识别：Qwen3-ASR-1.7B（bf16，本地 ModelScope 模型，D:\AI\models\modelscope）出文本；
   配 Qwen3-ForcedAligner-0.6B 出字级时间戳，按 jieba 词边界切句（≤20 字/行，≤28 字/句）
2. 清理：clean_transcript.py 按 filler_words.json 五组顺序
   （组合填充 → 口头冗余 → 句尾确认 → 语气词 → 句首填充）删除 / 改写口语词，
   保留守卫词（嘛 / 哈等只在词尾删）
3. 改稿：revise.py 七遍流程（P1–P7）无状态执行，逐遍提升书面度，最后 to_docx() 套公文版式
4. 交付：server.py 把以上封装成网页 API；前端单文件交互

备选引擎：Paraformer（约 13.5× 实时，更快但需热词），可用 --model 切换。
