整理稿对比识别原文 vs 云端整理稿

字幕轨永远是识别原文（带时间戳），整理稿只用于讲稿，不会改动字幕时间轴。 采用或回退都只影响讲稿，音画同步不受影响。

学习建议你在校对里反复做的修改，可一键沉淀成词表规则

工具只观察、不自动改词表：同一处修改出现过 2 次以上才会列在这里。 采纳后写入 terms/corrections.txt（错词校正）或 terms/aliases.txt（简称表）， 下次识别自动生效。一次误改不会被永久记住。

LLM 润色预览

用本地模型把口语转成书面讲稿，只改讲稿，字幕与时间轴一个字都不动。 检查分三级：阻断只在「严重截断 / 整篇复述」时出现； 待复核（术语、数字、条款号、末句、长度）可二次确认后照样采用； 其余为参考项。稿子长、跑得久，结果一律自动存盘，不采用也不会丢。

· 默认关闭思考：DeepSeek V4 默认先输出思维链，整理讲稿不需要， 关掉后同样的稿子更快、更省，也不会把 max_tokens 吃在 reasoning 上。
· 云端长稿按 3000 字一块（本地 700 字），3 万字约 10 次请求， 比原来 43 次少了 3/4 的提示词重复开销。

· API Key 只存本机 config/cloud_llm.json，已排除出 git；界面只显示脱敏串。
· 【新增 v2.4】每个预设的 Key 分开保存：填了智谱的再填 DeepSeek 的， 互不影响；切换下拉会自动带出该模型自己的 Key，留空即沿用。
