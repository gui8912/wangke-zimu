一、三分钟上手

  1. 双击 启动界面.bat（或在「服务台」里启动「网课转字幕」），浏览器自动打开

http://127.0.0.1:7870/。

  1. 把一节课拖进左侧虚线框 → 点「开始转写」。
  2. 跑完在右侧逐句校对 → 点「保存」→「下载字幕」选 SRT / VTT / TXT / Markdown。

顶栏最右侧的 「使用说明」 随时打开本手册（带目录、可新窗口打印 / 搜索），

不用翻文件。

别重复占磁盘（v2.4）：浏览器拖文件是 HTTP 字节流，浏览器不会告诉服务端

你的原始路径，所以只能把流落成 media/<编号>_<原名>（89MB 课件就占 89MB）。

想零拷贝就用上传框下面那行 「填本机路径 → 零拷贝导入」：直接写

D:\课程\第一课.mp4，服务端用 NTFS 硬链接登记（同一块盘两个名字指向同一份

数据，实测链接数 2、inode 相同、不额外占空间），转写、播放、导出一切照旧。

跨盘或权限不允许时才复制，界面会明确提示「跨盘已复制」。命令行批量

batch_add.py 一直就是这个机制。

另外 out/<课程名>.16k.wav 是 ffmpeg 抽的 16k 单声道音频（识别引擎只吃这个

格式，79 分钟约 152MB）；留着它下次重跑同一课件可以跳过抽取，不是无用副本。

out/_peaks/ 是波形缓存。这些中间产物都保留，只有 media/ 的源音视频禁止删除。

第一次用建议：先拿一段 2–5 分钟的课试跑，确认速度、术语、断句都合口味，

再排一整晚的批量任务。

二、单节课的完整流程

步骤操作说明
1 上传拖文件 / 点击选择 / 填本机路径mp4 / mkv / mov / mp3 / wav / m4a 等；多个文件直接拖进去会批量排队。拖文件会落一份副本，填本机路径用硬链接零拷贝
2 选参数顶部下拉识别源默认「本地 Qwen3-ASR · 精度优先」；语种默认中文
3 开关顶部复选框清理口语、数字规整、术语补全默认开；「云端整理稿」只在用云端识别源时可用
4 开始「开始转写」左中状态区显示进度，任务栏出现进度条 + 阶段 + 预计剩余
5 校对右侧字幕行点字幕行跳到对应时间；查找替换、合并碎句、时间轴整理、体检、文稿对齐
6 清理明细「清理明细」逐条看这次删了 / 改了什么，避免误删专业表述
7 保存 / 导出「保存」「下载字幕 ▾」导出前可在「导出设置」里选分段方式、空行、标点
8 改稿「改稿 →」七遍改稿流程；「LLM 润色」是可选用第 0 遍底稿
9 成稿「复制文本」一键把当前成稿放进剪贴板，直接粘贴到 Word（不再生成 docx）

改稿页的「复制文本」（v2.4）：原来的「导出成稿 ▾」是下拉菜单，点击只弹菜单、

再选格式才下载 Word 文档，依赖 python-docx 常失败，表现为「点了没反应」。

现在改成单按钮，一步复制到剪贴板，版式由你在 Word 里定。

双轨红线：字幕轨永远是识别原文 + 字级时间戳；讲稿轨才允许顺滑改写。

整段改写绝不进字幕层，否则时间轴会断，音画不同步。

因此：「LLM 润色」不会同步到字幕。润色的产出只进讲稿轨（改成稿、复制文本、

作为七遍改稿的第 0 遍）。想让字幕读起来更顺，走「重新清理」（只删口语、保留

每条起止时间）或逐句人工校对；术语替换也只在同一条字幕内部换词，时间码不动。

三、批量 / 夜间无人值守（重点）

3.1 网页端

左侧「任务」卡片 → 展开 「批量 · 夜间无人值守」：

  • 批量添加课件…：一次选多个文件；也可把多个文件一起拖到上方虚线框。
  • 定时开始：选日期时间 → 「设定」。到点自动开跑，不用守着；「取消定时」撤销。
  • 暂停队列 / 继续队列：白天要用机器时先暂停，晚上继续。
  • 失败自动重试：建议 1 次；失败任务自动排到队尾，别的课先跑。
  • 跳过已转录：同名同大小且已完成 / 已排队 / 识别中的文件不会重复入队。
  • 文件夹监控：勾上后，往 media/inbox/ 丢文件会自动排队（约 1 分钟内发现）。
  • 队列顺序：每条右侧 ↑ ↓ 调整先后，急用的课提到最前。

任务栏上方是批量操作条：**全选 / 反选 / 批量重试 / 批量取消 / 删除选中 /

清空已结束**。

删除只清任务记录和 out/_jobs/ 里的状态文件；out/ 里的字幕稿、
media/ 里的源音视频一律保留，工具不提供任何自动删除源文件的入口。
需要释放磁盘时，请自己在资源管理器里整理 media/。

每个识别中的任务显示 百分比 · 阶段（如「识别 12/28」） · 已用时：

Qwen3 路径逐片上报真实进度；Paraformer 是整段推理，百分比在跑完前不动，

但阶段与「已用时」会持续走动，不会看起来像卡死。队列被暂停或设了定时开始时，

排队任务会直接写明原因。

3.2 命令行 / 计划任务

python batch_add.py "D:/课程/*.mp4" "E:/录音/第一节.m4a"
python batch_add.py "D:/课程" --at "22:30"     :: 今晚 22:30 开跑
python batch_add.py "D:/课程" --at "+60"       :: 60 分钟后开跑
python batch_add.py --status                   :: 看队列
python batch_add.py --scan                     :: 只扫描 inbox

大视频不重复占磁盘：同一块盘建 NTFS 硬链接（秒级），跨盘才复制。

Windows 计划任务里把「程序」设为 Python 解释器、「参数」设为

batch_add.py "D:/课程" --at "22:30"、「起始位置」设为工具目录即可。

3.3 无人值守的三道保险

  1. 重启续跑：排队中的任务状态落盘，服务重启后自动重新排队；

只有「正在识别中」被强行打断的那一条需要手动点「重试」。

  1. 防休眠：识别中每 20 秒调用 SetThreadExecutionState 阻止 Windows 睡眠，

跑完立即释放，不改电源计划。

  1. 汇总报告：队列清空时自动写 out/队列报告.md，列出每节课的状态、

耗时、字数、失败原因——早上起来一眼看完。

合盖 / 断电 / 系统更新重启仍会中断当前任务；建议跑批量时接电源、
在系统设置里把「合盖」改为「不采取操作」。

四、讲稿润色：本地模型 / 免费模型怎么选

4.1 在哪里设置

「改稿」页 → 「润色模型设置」（就在「LLM 润色」按钮旁边）：

项填什么
后端本地模型（默认） / 云端 OpenAI 兼容模型
预设智谱 GLM-4-Flash（永久免费） / DeepSeek V4.1-Flash（低价 · 默认不思考） / 自定义
接口地址智谱 https://open.bigmodel.cn/api/paas/v4；DeepSeek https://api.deepseek.com
模型名glm-4-flash；deepseek-flash（旧名 deepseek-v4-flash 仍可用，deepseek-chat 已于 2026-07 停用）
API Key到 open.bigmodel.cn 或 platform.deepseek.com 注册后在控制台创建，粘贴一次即可
思考模式仅 DeepSeek 显示；默认勾选「关闭思考」（更快、更省、讲稿整理不需要思维链）
单价预设自动填好，只用于界面估算费用

点「测试连接」确认通了，再点「保存」。不填 Key 或把后端切回「本地模型」

随时回到纯本地，零外传。

每个预设的 Key 分开保存：填了智谱的，再切到 DeepSeek 填另一个，
两个互不覆盖；切换下拉会自动带出该模型自己的 Key，输入框留空即沿用。
「当前」一栏会显示本模型是否已存 Key、总共存了几个。
注意：只填 Key 还不够，要把「后端」选成「云端 OpenAI 兼容模型」才会真的用云端；
否则界面会提示「密钥已保存，当前仍是本地模型」。

DeepSeek 为什么要关思考（v2.7）：DeepSeek V4 系列默认先输出一段思维链，

reasoning_effort 还是 high。整理讲稿不需要推理，开着只会更慢、更贵，

而且思维链也算 max_tokens——实测 746 字一块的 reasoning 吃掉 1033 token，

正文容易被截断。现在 DeepSeek 预设默认勾选「关闭思考」，请求体传

thinking: {"type": "disabled"}；实测 210 字短稿 0.8 秒返回、输出仅 29 token。

想恢复思考就去掉勾选（仅 DeepSeek 端点会显示这个开关，GLM / Ollama 不发送该字段）。

本地模型实际怎么调用（不用填任何 Key、不联网）：把「后端」选成

「本地模型（默认）」保存，回改稿页点「LLM 润色」即可。模型是

D:\AI\models\llm\Qwen\Qwen3-4B-GGUF\Qwen3-4B-Q4_K_M.gguf（2.4GB），

第一次点润色才加载（懒加载，约 2.4GB 内存），纯 CPU 约 30 字/秒。

「润色模型设置」里点开就能看到模型是否就绪（不可用会写明原因并置灰按钮）。

模型目录可用 ASR_LLM_DIR 改。跑完先看 diff 预览和五项红线，点「采用」

才写成 <课程名>_润色 文件——不会自动覆盖原稿。

长稿自动分块（v2.4）：原来 8000 字会被硬拦，现在 3 万字也能一次跑完。

程序按 700 字整句切块（不切断句子）→ 逐块送模型 → 自动合并成一整篇 →

回传预览 → 确认后写入成稿。非末尾块的结尾句若被模型删掉，程序会自动补回

并在提示里报数量；原文真正的最后一句仍由界面「补回原末句」交给你决定，

红线闸门不会失效。前端与服务端超时按块数自动放宽（3 万字约 43 块，

本地模型可能跑 20 分钟左右），整体硬上限 20 万字（ASR_LLM_MAX_CHARS）。

想更快：在设置里切到 GLM-4-Flash（免费）或 DeepSeek，43 块通常一两分钟跑完；
想零外传就保持本地模型，晚上挂着跑即可。

安全边界：音视频识别永远在本机，云端模型只接收「讲稿文字」做润色；

字幕与时间轴一个字都不上云。API Key 只存本机 config/cloud_llm.json，

该目录已加入 .gitignore，界面只显示脱敏串。

v2.7 起云端长稿按 3000 字一块（本地仍 700 字），3 万字约 10 次请求，

提示词重复开销比原来的 43 次少约 3/4。

4.3 再省一点的六个习惯

  1. 识别一律本地；云端只开「LLM 润色」。
  2. 「LLM 润色」一稿只跑一次，之后的修改用本地七遍改稿 / 查找替换，不重复调模型。
  3. 批量任务勾「跳过已转录」，重复拖入同一批课件不白跑。
  4. DeepSeek 避开工作日 09:00–17:00（官方高峰价，约为低谷的 2 倍）；晚上、清晨、周末都是低谷。
  5. 专业术语、简称、漏字交给本地术语表与「术语补全」，不用花钱让模型猜。
  6. 先批量跑完识别，第二天集中校对时再统一润色，避免边跑边改造成重复调用。

润色结果要先过五项硬红线（术语、条款号、数字、末句、长度）才能「采用」；

界面会显示本次用了多少 token、约合多少钱。

4.4 长稿要等多久？结果会不会丢

3 万字讲稿：云端按 3000 字切成约 10 块（本地 Qwen3-4B 仍按 700 字切约 43 块），

云端 GLM-4-Flash 实测每块十几秒，整篇约 2–3 分钟；本地模型更久。

这期间正文不会变——整篇是

「全部块跑完 → 合并 → 一次性返回」，属正常，不是卡住。改稿页上方会显示

一条醒目进度条（百分比、块数、已用时间、预计剩余），「LLM 润色」按钮

同时显示 润色 3/10。想直接查状态，浏览器打开

http://127.0.0.1:7870/api/llm/progress，看 done / total / busy。

两条规定：

  1. 跑完之前不要关闭或刷新页面，也不要重复点按钮（会提示「已有稿子在润色」）。
  2. 跑完会弹出「对比预览 + 五项红线」，必须点「采用」才写入成稿；

只看到预览不等于已保存。

v2.4 补丁起，服务端在完成的瞬间把整份结果（含 diff 与红线）落到

out/_llm/last.json。此后即使刷新页面、断网、浏览器超时，甚至重启服务，

重新打开页面都会自动找回并弹出同一份预览，不必重跑十几分钟；同一份结果

只提示一次。首页也已改为禁缓存，避免浏览器拿旧脚本（旧版有 10 分钟强制

断开、也没有进度轮询，容易误以为「没反应」）。

五、性能：CPU 到底用满了没有

实测（20 核 Intel Ultra 7 265K / 63GB，真实课程 240 秒）：

方案墙钟整机 CPU峰值内存
顺序、torch 20 线程125s100%7.8 GB
顺序、torch 10 线程134s70%7.8 GB
2 路分片并行、各 8 线程99s（1.26×）93%9.5 GB

另一次 3 片样本：顺序 197s → 并行 108s（1.82×），

文本 100% 一致、字级时间戳 ±2ms 一致。

结论：单步自回归解码喂不满核心，减线程只会更慢；把多个分片并行才是正解。

默认 ASR_QWEN3_WORKERS=2（约 9–10GB 内存）。内存吃紧设 1，

余量大可试 3（每 +1 路约多 2–6GB）。

Paraformer 也做了并行（v2.4，300 秒真实课程，同一模型实例多线程）：

方案墙钟加速文本一致率
单路 4 线程（旧）17.5s1×100%
单路 20 线程16.5s1.06×100%
2 路分片并行8.7s2.01×98.9%
4 路分片并行6.2s2.82×96.8%

两个反直觉点：① 把单路线程拉到 20 核几乎没用（模型小，单路并行度有限），

只有切片并发才能喂满核心；② 同进程创建多个 FunASR 模型实例会直接段错误

（exit 139），所以实现是「一个实例 + 多线程」，实测稳定。

代价是切点附近约 1%~3% 的字差异（每片独立跑 VAD / 标点）。

v2.7 起默认并行度按机器自适应（核数 //4 与 内存GB //4，取小，上限 4）：

20 核 / 63GB → 4 路。复测 600 秒真实课程切 4 片：

并行每路线程墙钟CPU相对 2 路
2 路826.4s75%1.00×
3 路522.9s74%1.15×
4 路416.9s92%1.56×

79 分钟整课实测 185.6 秒（含 31.6 秒模型加载），旧基线 222.7 秒；

扣掉加载约 154 秒，折合约 1.45×。追求逐字精确（法规条文）仍可把

ASR_FUNASR_WORKERS 设 1，回到整段推理的零回归路径；内存吃紧设 2。

分片后每完成一片都会上报进度，长课不再停在 12%。

实测整条 79 分钟课件：整段单路 400 秒（6分40秒）产出 1431 条 / 21858 字；

用满 20 核的 Qwen3 要 40 分钟以上。占用率不是目标，端到端耗时才是。

七、常见问题

九、备份与迁移（重装电脑 / 换机）

顶栏「备份」按钮，专门解决「重装后词表和设置要重配一遍」。

操作说明
导出下载一个 zip：三张术语表、口语词规则、云端模型设置、队列偏好。勾「包含 API Key」会把 Key 明文打包，别外发；不勾则只备份设置
导入选 zip → 覆盖现有配置；导入前自动快照到 backups/import_<时间>/，导错可退回
不含media/、out/（音视频与字幕产物，按需另行复制，别塞进备份包）

换机步骤：旧机「备份」→ 导出（按需勾 Key）→ 拷到新机 → 装好本工具并启动 →

「备份」→ 导入 → 刷新页面。词表保存即生效，不用重启。

两个细节：队列导入后会自动解除暂停、清掉定时，避免「刚装好却一动不动」；

导入包里的路径严格按白名单匹配，../ 之类越权路径一律忽略。

本页由 samples/gen_manual.py 从 使用说明书.md 生成；修改说明书后重跑脚本即可。
