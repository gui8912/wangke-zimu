# 药品医疗器械监管网课 · 语音转字幕/文稿工具

**默认纯本地**（音视频不出本机）；自 1.3 起可选云端识别源，内容不涉密时可用。
适配药品、医疗器械监督管理专业术语。自 1.7 起可选**本地 LLM 润色讲稿**（模型也在本机）。

## 2.11 批量导入本机课件：拖放弹窗 / 剪贴板（2026-11-10）

网页受浏览器安全限制，**永远拿不到拖入文件的本地绝对路径**（File 对象只有
name / size / type），所以「拖到网页就零拷贝」做不到；直接拖进网页仍会上传一份副本。
现在由本机独立进程补上这个缺口，一次拿到多个完整路径再回写网页：

| 入口 | 怎么用 | 适合 |
|---|---|---|
| 「批量导入本机课件…」 | 点一下弹出本机窗口，把文件 / 整个文件夹拖进去，或点「浏览文件…」一次多选；点「导入到网页」 | 首选，一次几十个 |
| 「从剪贴板导入」 | 资源管理器选中多个文件按 Ctrl+C，再点按钮 | 文件夹已经开着 |
| 高级：手动填单个路径 | 折叠区里保留原来的输入框 | 临时补一个 |

- 路径回写后走 `/api/link/batch` 批量 NTFS 硬链接：同盘**零额外空间**，跨盘才复制
  并明确标出；逐条报错，一个失败不影响其余；成功后自动批量入队。
- 弹窗 `native_dropbox.ps1`（Windows 自带 WinForms）以独立进程调起，不阻塞服务；
  5 分钟无操作自动关闭；同一时刻只允许开一个。系统脚本宿主不可用时自动回退
  `native_io.py` 的纯 ctypes 原生多选对话框。
- 剪贴板读 `CF_HDROP`（资源管理器复制文件）或「复制为路径」的文本，
  支持 `file:///` URL、中文路径、斜杠归一化去重。
- 拖文件夹会递归展开里面的音视频；非音视频扩展名自动过滤。
- 新增：`native_io.py`、`native_dropbox.ps1`、`samples/test_v211.py`（48/48）。

## 2.10 播放进度记忆（2026-11-09）

一节课动辄一小时，字幕校对常要分几次做。「下次打开同一课件从上次位置继续」现已内置：

- **身份用「文件名+大小」**，不用 `file_id` / `task_id`：同一节课重新导入、重新排队
  后 id 会变，但文件还是那个文件，照样能续上。改名或大小不同会被视为另一节课。
- **两处都存**：浏览器 localStorage 立即生效，同时回写服务端 `config/playpos.json`
  （`/api/playpos`，最多 500 条）。v2.9 起端口会自动顺延，而 localStorage 按
  「协议+主机+端口」隔离——只存本地的话，端口一变记录就"消失"；服务端那份
  还能让换浏览器也续得上。写入用 `_atomic_write`，位置没变化不重复写盘。
- **节流 + 兜底**：播放中每 4 秒一次，暂停、切课件、切后台、关页面时各补存一次
  （`keepalive` 保证页面关闭也能送达）。
- **只记有用的位置**：开头 5 秒内、距结尾 15 秒内都不记，免得下次卡在片头或片尾。
- **界面**：续播时播放器下方显示「已从 12:34 继续播放」，带「从头开始」（清零并
  删除记录）与「✕」（只关提示）。不会自动开始播放，仍由你点播放键。
- 只记录秒数与时长，不含课件内容；`config/` 在 `.gitignore` 内，不进仓库。

## 2.9 端口自动分配 · 单实例保护（2026-11-09）

- **默认仍是 7870，但不再写死**：被别的程序占用时自动顺延 7871–7899；
  整段都被占才让系统给临时端口。实际地址在启动行里打印，浏览器也按实际端口打开。
- **不会起第二份**：启动前先在 7870–7899 里找「本程序」的 `/api/health`，
  找到就直接打开页面并退出。两个实例共用 `out/` 与队列，重复启动会互相抢任务，
  这条比「总能起来」更重要。
  端口决策放在导入 `transcribe` / `funasr` **之前**（`ports.py`），
  否则第二次启动会先拉起队列线程，可能抢走一条排队任务再退出，留下假 running。
- **实际端口落盘**：写入 `out/_port.txt`；`batch_add.py` 与 `samples/*` 测试脚本
  自动发现（先探活再信，被强杀留下的旧端口不会被误用）。
- **想固定端口**：`set ASR_PORT=7900`。此时若被别的程序占用会明确报错退出，
  不会偷偷换端口——固定端口是给「服务台/防火墙按端口探活」的场景用的。
- **服务台已改为动态端口**：`services.json` 的 `asr-pipeline` 去掉固定 `port`/`url`，
  改用 `urlPattern: listening on.*?127\.0\.0\.1:(\d+)` 从启动日志抓端口。
  机器识别行是**纯 ASCII**——服务台把 stdout 重定向后按 UTF-8 读，
  中文在管道里是 GBK 字节，正则匹配不到「服务已启动」，这点踩过。
- **任务卡加了手动刷新 + 时间戳**：右上角 `↻ 刷新`（转圈反馈），旁边显示最近一次
  更新时间；页面从后台标签页切回来会立刻补刷一次（浏览器会暂停后台定时器，
  原来要等下一个 2–6 秒周期，看起来像「不实时」）。
- **上传后服务重启不再要求重传**：`_enqueue_upload` 发现内存里没有该 `file_id`
  时，按 `media/<fid>_*` 找回并重新登记。实测救了 3 个 100MB 课件
  （上传完成、点入队之前服务重启，原来只能重传）。
- **长文件名不再变成 `xxx.mp4.mp4`**：截断前先摘掉扩展名再拼回。

### 润色红线：不再「一票否决」，改成三级

- **原来的问题**：五项全部 hard，任一不过就禁用「采用」。长稿里少一个术语、
  模型把末句合并、数字写法从「第一百二十条」变成「第120条」，都会让二十分钟的
  结果直接作废。
- **现在三级**：
  | 级别 | 项目 | 行为 |
  |---|---|---|
  | 阻断 | 严重截断（<0.4×）、整篇复述（>1.8×）、术语丢失过半 | 禁用「采用」，建议重跑 |
  | 待复核 | 术语、条款号、数字、末句、长度 | 允许采用，需**再点一次**确认 |
  | 参考 | 内容覆盖率、残留口语 | 只展示，不影响采用 |
- **数字 / 条款号归一化**：`第一百二十条 ≡ 第120条`、`百分之九十八点五 ≡ 98.5%`、
  `二零二六年 ≡ 2026年`，不再误报「改了数字」；只查原文数字有没有被打丢或改掉，
  模型把中文数字写成阿拉伯数字多出来的 token 不算错。
- **结果永不白跑**：润色完成即写 `out/_llm/last.json`；关窗、误点遮罩、刷新页面
  都能从改稿页「上次润色」找回；即使不采用也能「复制润色稿」。
  采用时的待复核项会写进提示，便于事后核对。

## 2.4 补丁三：刷新后自动载回字幕（2026-11-09）

## 1.9 长音频段错误修复（2026-11-08）

来自一次真实使用：服务空闲跑了 9 小时后接到一个 **79 分钟**课程，模型加载完 15 秒，
进程直接消失（exit 139 / SIGSEGV），任务状态永远停在 `running`、日志断在「模型就绪」，
前端连一句报错都没有。根因在 Qwen3-ASR 这条路径：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 把整段音频交给 `model.transcribe()`；库内部按 180s 切成 27 片后**整批**送进前向（默认 `max_inference_batch_size=32`） | 单次前向的 logits 就要几十 GB，进程被内存撑爆、段错误退出。原生崩溃在 Python 侧抓不到异常，只能表现为"任务消失" |
| 2 | 库默认 `max_new_tokens=512` | 180s 的中文片段约 700 字，超出部分被**静默截断**——就算不崩，长课也会悄悄丢字 |
| 3 | 库的切片函数在窗口过小时会原地打转 | 搜索半径大于窗口一半时切点落回起点附近，每轮只推进 1 个采样点（实测 12s 静音音频切出十几万片、内存涨到被系统杀掉） |

修复（`transcribe.py · _run_qwen3`）：

- **自己切片、逐片识别**：按 170s、低能量边界下刀，内存恒定在单片水平；每片失败先重试一次，仍失败才报错，且报错带片号与时间位置（`第 12/28 片（33.4 分钟处）识别失败`），不会 70 分钟的活白跑还看不出卡在哪。
- **时间戳拼回**：片内字级时间戳统一加片偏移再拼接，`align.py` 字级对齐与波形对齐全不受影响，双轨约束不变。
- 建模型时显式 `max_inference_batch_size=1`、`max_new_tokens=2048`（`ASR_QWEN3_MAXTOK` 可调）。
- 窗口夹在 **30–175s**、搜索半径压到窗口的 1/6（`ASR_QWEN3_WINDOW` 可调）。
- 服务启动开 `faulthandler`：再遇原生崩溃，各线程 Python 栈会追加到 `out/_crash.log`，不用靠猜。
- 逐片进度写进任务日志（`识别 12/28（33.4 分钟）：486 字`），长课不再"看起来卡死"。

真机实测（`samples/probe_v19_longaudio.py`，真实课程第 5–11.7 分钟，共 400 秒）：

| 项目 | 数值 |
|---|---|
| 切片 | 3 片（170s / 170s / 60s） |
| 产出 | 1958 字、1786 个字级时间戳 |
| 耗时 | 279 秒 = **1.44× 实时**（与前测 1.37× 一致） |
| 内存峰值 | **8.8 GB / 单片** |
| 时间戳 | 首 `[80, 400]`、末 `[399757, 399917]`，均在 400 秒内且单调 |

内存这一项正好解释了原崩溃：单片 170 秒就要 8.8 GB，原来 27 片同批前向
（默认批大小 32）意味着几十 GB 起步，63 GB 的机器也扛不住——段错误是必然结果，不是偶发。
所以 `ASR_QWEN3_WINDOW` 不建议往上调，除非确认内存余量够。

顺带修掉两处 v1.8 漏网的原子写问题：

- `_persist` 的临时文件名还是固定的 `<id>.tmp`（v1.8 只改了 `_atomic_write`），同时起两个实例会互相覆盖。
- `os.replace` 在 Windows 上偶发 `PermissionError`（杀软/索引服务瞬时占用目标文件）。实测高负载并发压测能撞到，现在瞬时冲突重试两次再报错。
- 任务被判定为「中断」时立刻落盘，磁盘状态不再停留在假的 `running`。

回归：`samples/test_v19.py` 26 项（假模型覆盖切片 / 偏移 / 拼接 / 重试 / 空片 / 参数夹取），
另有 `samples/probe_v19_longaudio.py` 拿真实课程音频做真机验证。

## 1.8 源代码审计修复（2026-11-08）

第三轮全量审计。四个 P1（其中两个会**静默产出错误结果**，比崩溃更危险）：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 导出「标点全角化」把英文缩写里的点也改成句号 | `GMP.GSP`→`GMP。GSP`、`No.5`→`No。5`、`e.g.`→`e。g。`。注释与文档一直承诺"不碰英文缩写"，实现相反 |
| 2 | LLM 输出被 `max_tokens` 截断时没有检测 | llama.cpp 截断只置 `finish_reason="length"`、不报错，代码把半截正文当完整结果。实测 343 字稿只剩 161 字 |
| 3 | 润色接口没有超时、锁也不会自愈 | 推理在 C++ 层跑、Python 侧中断不了；一旦卡死，锁永久占用，界面永远显示"正在润色" |
| 4 | 原子写的临时文件名固定为 `<name>.tmp` | 自动保存（1.2s 一次）与手动保存并发时会互相覆盖临时文件，后一个 `os.replace` 抛 `FileNotFoundError` |

修复方式：

- 标点：改成「前一个字符是中文、且后面不是数字」才把 `.` 转句号。中文语境的句点该转（`第一章.总则`），英文与数字里的一律不动。
- 截断：新增 `TruncatedOutput` 异常，`_polish_chunk` 检查 `finish_reason`；`_polish_with_split` 收到后**把该块对半切开重试**（最多 2 层），切不动才报错——不给残稿。
- 超时：`_LLM_BUSY` 记录开始时间，正常占用返 409，超过 `ASR_LLM_TIMEOUT`（默认 600 秒）返 503 并明说"疑似卡死、请重启"。前端另加 10 分钟 `AbortController` 兜底。
- 原子写：临时文件名加 8 位随机后缀，失败时清理，不再留垃圾。

P2 一并修掉：

- `_load_jobs` 遇到顶层非对象的 JSON（数组/字符串）会 `AttributeError` 带崩启动；排序时 `stat()` 也可能因文件被并发删除而抛错。两处都包进 try。
- `/api/reclean` 由 `async def` 改 `def`：它是纯 CPU 计算，放在事件循环里会挡住首页与任务轮询。
- 简称表加载时拒绝「全称里还含简称」的条目（`药品经营=>药品经营质量管理规范` 会让每次清理都膨胀一截）。
- `/api/llm/polish` 不再把 traceback 回给前端（含本机绝对路径）。
- `build_plain_text` 传非数组改为抛 `ValueError`（原来 `AttributeError` → 500）。
- `/api/terms` 词表损坏时返回 500 + 具体原因，不再裸抛。
- 极短文本（一句话不到 6 字）也报满五项硬红线，不再少一项。
- 转写日志落盘节流到 1 秒一次（原来逐行 `_persist`，一小时课程上千次写盘）。
- 模型查找结果缓存 30 秒（`/api/llm/status` 是高频调用，不必每次 rglob）。
- `polish()` 自带输入上限，命令行调用也拦得住。
- `DESIGN.md` 补上 1.6 / 1.7 的组件与反模式（此前停在 1.3）。

回归：`samples/test_v18.py` 16 项，既有 15 个脚本全绿；真实模型端到端
343 → 275 字、13.4 秒、五项硬红线全过、无截断误报。

## 1.7 讲稿层 LLM 顺滑（2026-11-08）

### 1.7.1 它是什么，以及它不做什么

改稿页新增「LLM 润色」按钮，用本地 Qwen3-4B-Instruct（GGUF Q4_K_M，2.33 GB，
llama-cpp-python 纯 CPU 推理）把口语转写整理成可读底稿，作为七遍改稿的
**第 0 遍**——之后仍走人工七遍。

**它只作用于讲稿层。字幕（cues + 字级时间戳）一个字都不碰。**
整段改写会打断 `align.py` 的字级对齐、导致音画不同步，这条红线在 1.3 的双轨
设计里已经写死，这里继续遵守。

### 1.7.2 为什么直接对原文做，而不是接在规则清理之后

PoC（`samples/LLM_PoC报告.md`）实测，两条路径结果不同：

| 路径 | 效果 |
|---|---|
| B：LLM 直接对原始识别稿 | 343 → 275 字，末句保留，术语 11 条全保留 |
| C：先规则清理再 LLM | 口语更干净，但**把结尾「那今天就到这里，谢谢大家」整句丢了** |

推测是规则先删掉衔接词后文本更紧凑，模型更容易把剩下的当冗余压掉。
所以这里走 B，规则清理留给人工的第 1、5 遍。

### 1.7.3 三道闸门（缺一不可）

1. **五项硬红线**，任一不过则「采用」按钮禁用：
   术语保留（清单来自 `terms/`，不硬编码）、条款号保留、数字保留、
   **末句保留**、长度合理（0.6–1.25×）。
   末句那项是专门加的：实测模型高频把结尾客套话当冗余删掉，而术语/数字/长度
   四项全过，肉眼在几千字稿子里根本发现不了。
2. **强制 diff 预览**：逐句对照 + 润色后全文，看过才能采用；接口本身不落盘，
   绕过预览就没有保存入口。
3. **采用后另起 stem**（`原stem_润色`），原稿 v0 不动，随时可回溯。

「残留口语」「内容覆盖」是**参考项**，不参与拦截——LLM 会重组句子，
覆盖率低不必然等于丢内容；而「这个/那个」后面跟名词、删了不通，正是 LLM 的增量所在。

### 1.7.4 实测（`out/test_lesson.raw.txt`，343 字真实识别稿）

| 项 | 结果 |
|---|---|
| 耗时 | 13.3 s / 343 字（12 线程，CPU），约 26 字/秒 |
| 字数 | 343 → 275（0.80×） |
| 术语 | 11 条全部保留（两品一械、药品经营质量管理规范、药品上市许可持有人、飞行检查、挂靠经营、走票过票、一致性评价、中药饮片、UDI…） |
| 硬红线 | 五项全过 |
| 口语 | 「嗯/呃/那么/就是说」清除，仅剩 1 处「这个」 |

**代价与边界**：13 秒是 343 字的量；1 万字约 6 分钟，单次上限 8000 字
（超出请分段）。模型常驻内存 2.4 GB，首次点击才加载。模型缺失或
llama-cpp-python 未装时，按钮置灰并写明原因，不伪造结果。

**兜底**：若只是末句丢了，弹窗底部会给「补回原末句」——把原文最后一句原样
接回去并重算长度项。不静默替模型补，是因为那样闸门会变成永远通过，
掩盖模型真实行为。

### 1.7.5 用法

```bash

# 命令行单独跑（不启动服务）
python -c "import llm_polish as L;print(L.polish(open('稿.txt',encoding='utf-8').read())['polished'])"
```

## 1.6 导出格式选项与清理明细（2026-11-08）

### 1.6.1 导出不再只有「每句一行」

字幕是按屏断行的，直接导出会得到一堆半句。现在 TXT / Markdown / 复制全文
共用一套导出设置（存在浏览器本地，下次沿用）：

| 选项 | 取值 | 说明 |
|---|---|---|
| 分段方式 | `para`（默认）/ `line` / `raw` | `para` 按句末标点收段，屏断行自动合并成完整句子 |
| 段间空行 | 开 / 关 | `line` 与 `raw` 本来没有段落概念，不受此项影响；Markdown 强制空行 |
| 标点风格 | `keep`（默认）/ `full` / `half` | 全角化**只转中文字符后的标点**，`98.5%`、`3.14` 的小数点不会被改 |

字幕 SRT / VTT 不受影响——时间轴必须按条分割。

### 1.6.2 「清理明细」：看得见删了什么

原来只能在导出的 `report.md` 里看变更，界面上看不到。现在校对工具条多了
「清理明细」：左原文、右清理结果、右侧标变更类型（语气词 / 术语补全 / 数字规整）。

实现上，`run_pipeline` 在 cue 级清理时收集 `cue_changes` 一并返回；
`/api/reclean` 也返回 `diffs`。历史任务不保存这份明细（`result` 不落盘），
点一次「重新清理」即可生成。

### 1.6.3 顺带修掉一个潜伏故障

`esc()` 转义函数在 v1.5 写「学习建议」弹窗时被调用但**从未定义**，
打开弹窗直接 `Uncaught ReferenceError`。v1.6 做「清理明细」时被同一个错误撞出来，
已补到脚本最前面。教训：UI 改动必须真机打开弹窗验证，`node --check` 查不出这种问题。

## 1.5 术语修复与修订学习（2026-11-08）

针对网课现场三个真实问题：**老师用简称**、**术语说漏一两个字**、**语速快导致识别含混**。

### 1.5.1 简称膨胀（`terms/aliases.txt`）

`GSP要求企业…` → `药品经营质量管理规范要求企业…`

为什么必须用显式表：简称与全称之间没有字符相似性。实测 `GSP` 在 125 条术语表里
模糊匹配最高只有 **29 分**（最像的是「上市前GMP符合性检查」），任何 fuzzy 算法都认不出。

英文缩写按「前后不是字母数字」整词匹配，所以 `GSP认证` 能展开，`GDP` / `GSPX` 不会误伤。

### 1.5.2 漏字补全（`termfix.py`）

`药品经营质量规范` → `药品经营质量管理规范`（补「管理」）

用术语表做近似匹配，但**三条硬约束缺一不可**：

| 约束 | 不加会怎样 |
|---|---|
| 只补「比术语短」的片段 | `按照药品管理法实施条例` 会把「按」字吃进候选 |
| 首尾必须都对得上 | `依据药品管理的规定` 会被误补成 `药品管理法`（末字「理」≠「法」，判为截断） |
| 强上下文才自动改 | 无上下文时补全全靠猜，误改面不可控 |

强上下文 = 前置 `依据/根据/按照/遵照/执行/符合/违反/落实/对照/《`，
或后接 `第/规定/要求/明确/指出/所称`。弱上下文**只出建议**，不改原文。

实测：4/5 正样本正确检出，**6/6 负样本零误改**；性能 2.4 ms/句，
加 3-gram 短路后 0.2 ms/句（1000 句不到半秒）。

### 1.5.3 修订学习（`learn.py` + 「学习建议」按钮）

**只观察、不自动应用。** 你在校对区改的地方会被记录，同一处修改出现 **≥2 次**
才列为候选，逐条点「采纳」才写进 `corrections.txt` / `aliases.txt`。

三条防污染设计：

- 自动保存每 1.2 秒一次，同一内容**只记一次**（否则任何一次误改都会被刷成「高频」）
- 用 jieba 做**词级** diff：字符级会把 `质量规范→质量管理规范` 扩成
  `营质量规范的→营质量管理规范的` 这种带脏边界、没法审的片段
- 句子数差异过大判为「换了来源」（比如改用讲义对齐稿），整次不学习

一次误改不会变成永久规则 —— 这是 human-in-the-loop，机器找规律、人拍板。

### 1.5.4 顺带修掉两个真缺陷

- **P0：`第二十条` 被数字规整成 `第二10条`**。原来只用 `(?<!第)` 前缀断言，
  但「十」前面是「二」不是「第」，保护失效。改为**整体遮蔽**条款号
  （`第X条/款/项/章/节/编/部分`），做完其余规整再原样放回。
- **字幕行不能点击跳转**。校对时无法「点一句、听一句」，只能拖进度条。
  现在单击整行跳到该句起点（点时间输入框、正在编辑文本时不跳）。

### 1.5.5 开关

前端「术语补全」复选框（默认勾选）、CLI `--no-termfix` / `--termfix-suggest-only`、
接口 `termfix` + `termfix_auto`（`/api/transcribe`、`/api/reclean`）。

### 1.5.6 语速含混为什么救不了

含混导致的是**多字连错**（「质量关规范」「企业建质量」），fuzzy 只对 1–2 字缺漏有效，
连错三个字以上相似度就掉到阈值下。这类只有三条路：提升识别层、用 `align.py` 的
`warn` 标记（相似度 <0.75 自动标黄）逐句复核、或交给 LLM 纠错。

**最优解仍是讲义对齐**：实测把「药品经营质量管理规范要求企业建立质量管理体系」
分别做成漏 2 字 / 漏 4 字 / 用简称 / 同音错字 / 语速含混，`align.py` 的相似度分别是
0.900 / 0.875 / 0.889 / 0.955 / 0.850，**全部能对齐且输出讲义原文**。
有讲义时，漏字、简称、错字三件事一次解决，不需要补字算法。

## 1.4 受限 ITN 数字规整（2026-11-08）

**背景**：ASR 本身已商品化，差距在转写之后。市面上的 ITN 工具（`wetext`、`cn2an.transform`）
做的是**全量**数字规整，会把「第一百二十条」写成「第120条」，把「四不两直」
「双随机一公开」这类含中文数字的固定表达一起改坏——在监管材料里这是硬伤。

**做法**：新增 `itn_zh.py`，用**白名单**而不是黑名单。只有命中下面 5 类明确计量模式才转，
其余一律不动：

| 模式 | 例 | 说明 |
|---|---|---|
| 百分比 | 百分之九十八点五 → `98.5%` | 含小数 |
| 四位年份 | 二零二六年 → `2026年` | 限 1900–2100，越界不动 |
| 月日 | 六月一日 → `6月1日` | 月 1–12、日 1–31 校验 |
| 数量词+单位 | 三百五十家 → `350家`、五十万元 → `50万元` | 数值 ≥10 才转，个位数保留汉字 |
| 文号 | 第七百三十九号 → `第739号` | 阿拉伯数字是正式写法 |

**永不改动**（各有一条回归用例守着）：

- 法规条款号：`第一百二十条`、`第五条第二款`、`第三章节`…（`第` 字前缀直接排除）
- 监管固定表达：`四不两直`、`双随机一公开`、`四个最严`、`三品一械`、`十四五`
- 成语与惯用语：`一刀切`、`一揽子`、`第一时间`、`三令五申`…

**为什么不用 wetext**：它依赖 `pynini`（需 OpenFst 本地编译），Windows 上装不上；
而且它做全量 ITN，在这个场景是负价值。本方案只依赖 `cn2an`（纯 Python，
`pip install cn2an`），缺失时自动降级为原样返回 + 一条警告，不会让服务启动失败。

**接在哪一层**：只作用于**清理层**（`*.clean.srt` / `*.clean.txt`）。
`raw.srt` 保持识别原样，符合「原稿 v0 不覆盖」原则。ITN 只改数字写法、
不改字不删词，对时间轴与 `align.py` 对齐无影响。

- 开关：前端顶栏「数字规整」复选框（默认勾选）、CLI `--no-itn`、
  接口 `itn=true|false`（`/api/transcribe`、`/api/reclean`）。
- 回归：`python samples/test_itn.py`（17 项）。

## 1.3 可插拔识别源与双轨整理稿（2026-11-08）

**背景**：用户确认音视频可出本机、可在云端运行、内容不涉密。调研
`yc-2018/DoubaoVoiceIME`、豆包输入法「智能文字整理」、微信输入法「文字整理 / AI 录音笔」
后，决定不照搬逆向 SDK，而是接官方云 API，并把「字幕」与「讲稿」分轨。

**为什么分轨**：云端顺滑 / 口语转书面语会改字。若直接拿整理稿做字幕，
`align.py:159` 的字级时间戳对齐（rapidfuzz，阈值 55）会失效、音画不同步。

```
云端 ASR 一次调用
 ├─ 轨 A 字幕轨 subtitle = 原文 + 词级时间戳 → SRT/VTT、波形、align.py   ← 一个字都不改
 └─ 轨 B 讲稿轨 script   = 顺滑/书面语文本 → revise.py 七遍改稿 → DOCX/MD ← 允许改措辞
```

- 新增 `asr_providers.py`：Provider 抽象层 + `Tracks` 双轨结构 + 厂商响应映射纯函数 +
  diff / 一键回退。密钥只走环境变量，**不写仓库**。
- 本地源 `local-qwen3`（默认）/ `local-paraformer` 行为与 1.2 **完全一致**，零回归。
- 云端骨架 `tencent-cloud`（腾讯云 `ResTextFormat=5`，`FinalSentence`+`Words` 原文轨、
  `WrittenText` 整理稿轨）、`volcengine-doubao`（豆包语义顺滑 + 请求级热词）。
  **本版只提供可插拔骨架与字段映射，HTTP 调用待接入**；未配置密钥时下拉置灰、
  提交任务拦为 400，不会发请求、不伪造文本。
- 新增接口：`/api/providers`、`/api/tracks`、`/api/diff`；`/api/health` 升 1.3。
- 前端：顶栏「识别源」下拉、「云端整理稿」开关（默认关；勾选后跳过本地口语清理，
  避免同一次识别产出两份互相竞争的整理稿）、「整理稿对比」弹窗
  （左原文 / 右整理稿逐段标差异）、一键恢复识别原稿、用整理稿另起一份改稿。
- 产物：`<stem>.tracks.json`（双轨）、`<stem>.script.txt`（讲稿轨，仅有整理稿时生成）；
  原 `<stem>.json` 结构不变，align.py / 历史任务照常工作。
- 回归：`python samples/test_providers_v13.py`（18 项）；既有全套回归全绿。

**接入云端前需要**：开通腾讯云或火山引擎账号，配置下列环境变量（勿写进 config 或仓库），
再实现 `asr_providers.py` 里两家 provider 的 `_submit` / `_poll`：

| 源 | 环境变量 | 备注 |
|---|---|---|
| 腾讯云 | `ASR_TENCENT_SECRET_ID`、`ASR_TENCENT_SECRET_KEY`、`ASR_TENCENT_APPID` | `ResTextFormat=5` 增值付费；音频需公网可达 URL，base64 仅 <5MB |
| 火山引擎 | `ASR_VOLC_APP_KEY`、`ASR_VOLC_ACCESS_KEY`、`ASR_VOLC_SECRET_KEY` | 录音文件识别 0.8 元/小时；音频 <5 小时且 <512MB |
| 通用 | `ASR_PROVIDER` | 默认识别源；云端未配置时自动回落本地 |

**术语保护**：云端热词表用 `asr_providers.hotword_terms()` 从 `terms/hotwords.txt` 生成
（每词 <10 字，超长的「药品经营质量管理规范」等会被剔除，需人工复核）。
云端自带的 ITN 或 LLM 顺滑仍可能替换监管术语，**必须保留轨 A 原文并人工核对**。

### 口语词实时维护

点「编辑口语词」，弹窗里分**五类**，对应规则文件 `rules/filler_words.json` 的 `groups`：

| 类别 | 处理方式 | 说明 |
|---|---|---|
| 语气词 | 无条件删除 | 嗯、啊、呃、哦、诶、哎、嘛、哈 |
| 句首填充 | 仅句首删 | 这个、那个（无指示对象时）、就是说、那么 |
| 句尾确认 | 仅句尾删 | 对吧、是吧、是不是、好不好、行不行 |
| 口头冗余 | 整体删 | 怎么说呢、那个啥、这样的话、所以说 |
| 组合填充 | 优先整段删 | 这个就是说呢、那么就是说、然后的话 |

改完保存，点「重新清理」立刻用新词表重跑一遍，不用重新识别。原始字幕始终保留，随时可以换词表重来。

**界面里各词用空格分隔、一行展示**（不再一词一行）。词多的时候按行排会拉得很长，编辑时要一直往下滚；空格排开后一屏就能看全，改词、加词都快。

**分隔写法不限一种**，下面这几种写法结果完全一样：

```
呃 嗯 啊            空格 / 全角空格（界面默认用这个）
呃、嗯、啊          顿号
呃，嗯，啊          中文逗号
呃,嗯,啊            英文逗号
呃；嗯;啊           分号
1、呃 2、嗯          带编号（编号会自动去掉）
- 呃  - 嗯          带项目符号
"“呃”、“嗯”"      带引号（引号会自动去掉）
每行一个            换行也照样认
```

也可以随意混着写，例如 `哦, 唉、呀 吧` 会被拆成 4 个词。右侧实时显示“共 N 个”，保存前就能确认有没有拆错。

**唯一的例外**：如果某个词本身含空格（例如英文口头语 `you know`），要用引号包住，否则会被拆成两个词：

```
"you know" 呃        → ["you know", "呃"]
you know 呃          → ["you", "know", "呃"]
```

当前词表共 **101 个词**（词源来自法律转录稿校对、演讲口头禅分类、对白整理规范等多份清单）：

| 类别 | 词数 | 内容 |
|---|---|---|
| 组合填充 | 18 | 这个就是说呢、然后的话、然后呢就是、这个那个… |
| 口头冗余 | 35 | 怎么说呢、你知道吗、说实话、坦白讲、我跟你讲、你看、好嘛… |
| 语气词 | 30 | 呃额嗯唔嘶唉哦喔咦噢啊呀诶哎嘿 + 嘛哈嘞咧啦呗哇哟呢吧（后 10 个只删句尾） |
| 句首填充 | 9 | 这个、那个、就是说、那么、那什么、这一块… |
| 句尾确认 | 9 | 对吧、是吧、是不是、好不好、行不行、对不对… |

**处理顺序是固定的**：组合填充 → 口头冗余 → 句尾确认 → 语气词 → 句首填充。长短语先删，单字最后——否则「对吧」会被单字「吧」拆成「对」，「这个就是说呢」会被拆成「这个」+「就是说」。

**为什么句尾确认不收「懂吗 / 可以吗 / 听明白了吗」**：这些是实义问句，删掉「懂吗」，「这个道理你」就断了。只收删掉之后主句仍然完整的附加确认词。

**一个已知取舍**：语气助词「吧」会被删，祈使句会变硬——「走吧」→「走」。如果某篇稿子需要保留这种语气，把它从词表里删掉即可。

**会长误删的保护**：`嘛/哈` 只在句尾删（不伤「干嘛」「哈哈」）；`吧` 排除「酒吧/网吧/氧吧/咖啡吧/贴吧」；`呢` 排除「你呢/我呢/他呢」；`你看` 只在后接标点或句末时删（不伤「你看那边」）。

### 哪些词不删、只给建议

有七组词要看上下文，工具不擅自改，只在结果上方列出「待人工判断」：

| 词 | 什么时候删 | 什么时候保留 |
|---|---|---|
| 我们／咱们 | 泛称引导「我们来看…」→ 删「我们」 | 单位自称（后接监管、要求、局、单位、规定…）→ 建议改「我局／本单位」，**不删** |
| 这个／那个 | 后接标点（这个，那个、）→ 无论位置都删 | 后接名词（这个文件、那个条款、这个批号）→ 保留 |
| 实际上／其实／事实上 | 后接标点是口头禅 → 删 | 后接「是、但是、而是、并非、相反、却」→ 保留 |
| 基本上／大概／差不多 | 无信息填充 → 删 | 后跟数字、法条、金额 → 保留并提示回听核对 |
| 应该讲／可以说／换句话说 | 当填充语 → 删 | 有解释功能 → 建议精简为「即」 |
| 大家可以看到／请注意 | 同一篇超过 2 次的部分删 | 课件引导句 → 建议精简为「注意／参见」 |
| 嘛／哈 | 只在句尾删 | 「干嘛」「哈哈」「喇嘛」「哈佛」不动 |

**为什么不全自动**：正式稿不能含糊。「大概三十个工作日」里的「大概」删掉就变成确定值，「我们的监管要求」删掉「我们」就丢了主体。这类判断机器做不准，宁可留给人工，也不能改错。

改稿工作台的第 1 遍面板里也有「编辑口语词表」入口，改完回到原处点「重跑本遍」即可。

### 字幕体检

工具栏「体检」按 Netflix / EBU 的字幕规范逐条检查：

| 指标 | 标准 | 说明 |
|---|---|---|
| 阅读速度 | ≤ 9 字/秒（超过 12 判致命） | 中文按字计，EBU 是 12–16 字符/秒 |
| 单条时长 | 最短 0.83 秒，最长 7 秒 | Netflix 833ms / EBU 7s |
| 单条字数 | ≤ 20 字 | Netflix 中文每行 16 字，最多两行 |
| 相邻间隔 | ≥ 0.12 秒 | 间隔太小画面会闪，重叠是硬错误 |
| 空字幕 | 只有标点 | 直接提示删除 |

每条问题都能一键处理：**定位**跳到那一句、**延长这条**、**拆成两条**（在标点处断，时长按字数比例分）、**并入上一条**。

底部的「一键修复时间轴」只调时间不动文字：压掉重叠、补足最小间隔和最短停留。遇到前后没余量的极短句，它会老实告诉你改不动——那种情况要靠拆分或合并。

### 撤销与重做

工具栏的 ↶ ↷，或 `Ctrl+Z` / `Ctrl+Y`。撤销覆盖：手动改句、查找替换、重新清理、拆分、合并、体检修复、删除空字幕。历史保留 80 步，转写出新结果时清空。

`重新清理` 会用原始字幕重跑，**会覆盖手工修改**——所以有改动时会先弹确认，撤销也能回来。

### 主题与字号

- **A小/中/大/特大**：四档字号，正文和字幕列表一起变。

设置存在本机浏览器里，下次打开还在。首次访问会跟随系统的深色模式设置。也可以用 `?theme=dark` / `?theme=light` 直接指定（截图、分享时方便）。

## 七遍改稿（口播稿 → 阅读稿）

顶部「**改稿**」标签是和转写并列的第二个工作区。转写解决"听不清"，改稿解决"读不动"。

核心是**分遍，不是一次改好**。第一遍就想让稿子"像写的"，会把讲话人的声音整个抹掉——那是录音里最值钱的东西。

| 遍次 | 动作 | 谁来做 | 界面里能做什么 |
|---|---|---|---|
| 原稿 | 备份 | — | 粘贴转写稿，或一键载入当前转写结果 |
| 1 | 删填充词 | 工具 | 看删了什么、删了多少；可给某个词「保留 2 处」 |
| 2 | 分段 | 工具 | 三段密度可选；不满意直接回车手动分段 |
| 3 | 去绕圈 | 你判断 | 工具列出相似句对照，你点「留前句」或「留后句」 |
| 4 | 语法修复 | 工具建议 + 你确认 | 量词冗余、句式杂糅、时间词重复、指代不明、空话套话 |
| 5 | 书面化 | 你按语境选 | 「然后」给 4 个选项，不搞统一替换 |
| 6 | 事实核对 | 必须人工 | 自动挑出数字、法条、日期、期限，逐条打勾 |
| 7 | 通读朗读 | 必须人工 | 一键合成朗读音频，边听边改 |

**分遍的规矩写在代码里**：

- 原稿单独存 `v0.md`，任何一遍都不会覆盖它
- 每跑一遍存一个版本文件（`v1.md` … `v7.md`），随时可以退回来看
- 工具只做能确定的事；不确定的一律只标注、给建议，不擅自改写
- 不生成任何新的事实、数字、法条名

版本文件位置：`out/rev/<稿件名>/v0.md … v7.md`。

**导出**：右下「导出成稿 ▾」可选 Word（公文版式：标题方正小标宋二号、正文仿宋_GB2312 三号、行距 28 磅）、Markdown、纯文本。

> 一个提醒：第 1、2 遍可以完全交给工具，第 3 遍以后的判断和第 6 遍的事实核对**必须人工**。转录稿改阅读稿最容易出硬伤的地方就在这里。

## 命令行

```bash
# 单文件，识别 + 自动清理
python transcribe.py -i 网课.mp4 --clean

# 只要识别（出 SRT，带时间戳）

# 批处理整个目录
python transcribe.py -i ./课程/

# 换引擎：速度优先
python transcribe.py -i 网课.mp4 --model paraformer

# 【1.3】指定识别源（默认 local-qwen3，等价上例第一行）
python transcribe.py -i 网课.mp4 --provider local-qwen3
# 云端源有整理稿时，跳过本地口语清理避免双重改写（需先配密钥并接入 HTTP）
python transcribe.py -i 网课.mp4 --provider tencent-cloud --use-script-track
```

## 三步工序

| 工序 | 工具 | 做什么 | 能否回滚 |
|---|---|---|---|
| 1 识别 | `transcribe.py` | 音频→文字+时间戳，热词偏置 | 重跑即可 |
| 2 清洗 | `clean_transcript.py` | 五类填充词、七组上下文判别、校正错词 | 有变更报告，建议单列 |
| 3 精修 | `prompts/llm_clean.md` | 语义型冗余、分章节 | 保留原文对照 |

工序 2 是纯规则、确定性、零成本，先跑它；工序 3 才需要 LLM。

## 术语表怎么维护

**热词表** `terms/hotwords.txt`：每行一个词，`|` 后可指定权重（默认 20）。
建议维持在 100–300 条，超过 500 条会拖慢解码。只放"老师一定会说、且模型大概率听错"的词。

**校正表** `terms/corrections.txt`：`错误词=>正确词`，一行一条。
只放"几乎不可能正确"的同音误写。有歧义的（如 储备/贮藏）放文件末尾注释掉，人工确认后再启用。

这两张表是这套方案里**性价比最高的部分**。识别错了改模型收益很小，改词表收益很大。

## 常见坑

1. **pip 装不上包**：pip 26 无法解析国内镜像的索引协议（repository-version 1.0）。降级 `pip==25.3` 即可。
2. **ModelScope 联网校验**：脚本已设 `disable_update=True`。若仍卡住，把模型预先下到本地再传路径。
3. **ffmpeg**：用 `imageio-ffmpeg` 自带的二进制，无需单独安装。
4. **纯内网环境**：首次需联网下载模型（Paraformer 全家桶约 1GB），之后可完全离线。
5. **数字规整依赖 `cn2an`**（1.4 起）：`pip install cn2an`。这是纯 Python 包，
   无需编译；未安装时数字规整自动跳过并告警，其余功能不受影响。
   不要改用 `wetext`——它依赖 `pynini`，Windows 上需要 OpenFst 本地编译，装不上。

## 本机实测（2026-10-26）

测试样本：`samples/test_lesson.mp3`，71.6 秒模拟药监讲课音频（含口语词与 12 个专业术语）。

| 指标 | Paraformer | Qwen3-ASR-1.7B |
|---|---|---|
| 识别耗时 | 5.3 秒 | 52.3 秒 |
| 实时倍率 | **13.5 ×** | **1.37 ×** |
| 1 小时网课 | 约 4.5 分钟 | 约 44 分钟 |
| 模型加载 | 32 秒 | 15 秒（bf16，本地缓存） |
| 热词偏置 | 支持 | 不支持 |
| 无热词时「两品一械」 | 良品一泻 ❌ | 正确 ✅ |
| 句间粘连 | 明显（两句话会粘一起） | 基本没有 |
| 时间戳 | 字级 | 字级（强制对齐） |

**怎么选**：偶尔转一次、要快 → Paraformer + 热词表。量大、较真准确度、可以挂着跑 → Qwen3-ASR。

**热词实证**：Paraformer 关闭热词时「两品一械」被识别为「良品一泻」，开启后正确，其余句子无副作用。Qwen3-ASR 靠 LLM 语义理解，不用热词也对，这也是它慢的代价所在。

**精度现状**：术语层已全对，剩余错误集中在三类——
1. 同音替换（「储运」→「储存」、「再看」→「在看」）
2. 虚词增生（「炮制是也是有规范的」多一个「是」）
3. 少数句间粘连（Paraformer 更明显）

这三类规则层救不回来，交给 `prompts/llm_clean.md` 的 LLM 精修。
